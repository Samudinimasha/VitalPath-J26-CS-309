Ambulance AMB-CMB-07 · edge gateway · runs before any telemetry is accepted

Is this ambulance device who it claims to be, and how far should we trust it?

Connected-ambulance frameworks accept telemetry from any registered gateway with a yes/no check. A cloned, impersonated or failing IoMT device can inject false vital signs before any later security layer sees them. This engine replaces the binary check with a quantitative Trusted Device Score and three graduated access tiers.

T = 0.30·C + 0.25·F + 0.20·H + 0.15·B + 0.10·R
T ≥ 0.80FULL TRUSTTelemetry admitted. Re-verified every 300 s.
0.60 ≤ T < 0.80CONDITIONALAdmitted with monitoring flags on weak factors. Re-verified every 60 s.
T < 0.60 or identity failureBLOCKEDNo telemetry. Alert raised. Unknown devices are REJECTED before scoring.

Decision pipeline for one connection attempt

trust/engine.py
1 · ADL GATE

Registered?

Device ID must be on the Authorised Device List and active. Otherwise REJECTED, never scored.

2 · FACTORS

C, F, H, B, R

Each factor is scored 0.0 to 1.0 and combined into T with fixed weights.

3 · IDENTITY GATE

Hard failures

Forged, expired, revoked or wrong-identity certificate, or cloned hardware, blocks the device whatever T says.

4 · TIER

Graduated access

Full trust, conditional with monitoring, or blocked. Every decision is written to trust_decisions.

The five factors

FactorWeightWhat it measuresStatus
C Certificate validity0.30X.509 chain to VitalPath Root CA, validity period, CRL, CN binding, pinning, clientAuth EKU, renewal windowBUILT
F Fingerprint match0.25Hardware ID and MAC against the registered values, constant-time SHA-256 comparisonBUILT
H Device health0.20Battery, sensor error rate, firmware version, heartbeat ageBUILT
B Behavioural consistency0.15Transmission pattern against the device's baselinePROVISIONAL · PP2
R Historical reputation0.10Computed from this device's past decisions in trust_decisionsPROVISIONAL · PP2

B and R are accepted as inputs for PP1 and marked "provisional" in every decision message. The decision log that R will be computed from is already recorded.

Why identity failures are gates

The weighted formula alone lets attackers through. C and F together are only 55% of T, so a device with C = 0 or F = 0 but healthy H, B, R still scores 0.675 to 0.735, which is conditional access.

AttackT aloneFormula alone saysEngine decides
Clone with stolen cert + key0.735CONDITIONALBLOCKED · FINGERPRINT
Clone with forged cert0.685CONDITIONALBLOCKED · CERTIFICATE
Expired certificate0.675CONDITIONALBLOCKED · CERTIFICATE
Revoked certificate0.675CONDITIONALBLOCKED · CERTIFICATE

Softer problems stay in the score and give graduated behaviour: a certificate near expiry (C = 0.75), a MAC changed after repair (F = 0.60), and degraded health, behaviour or reputation.

trust/registry.py · SQLite table authorised_devices

    
Authorised Device List

    
Every IoMT device must be registered before it can send telemetry. At registration the certificate's SHA-256 fingerprint is pinned, along with the MAC address and hardware ID used by the Fingerprint factor. Lookup happens before scoring.
